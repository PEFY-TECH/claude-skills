# PEFY-GG UI/UX governed design adapter

This skill is a **governance companion** to the third-party UI UX Pro Max engine, not a replacement for or unverified copy of that engine. It is available only in repositories/environments where this directory is actually installed or checked out.

## Canonical source

- Official upstream: https://github.com/nextlevelbuilder/ui-ux-pro-max-skill (MIT; preserve licence/attribution).
- Approved current package family: `ui-ux-pro-max-cli` (binary `uipro`), **not** legacy `uipro-cli`.
- Source staging PR/reference: https://github.com/yemanlin1st/ui-ux-pro-max-skill/pull/1
- Do not install or update third-party packages automatically. Require exact reviewed release and separate package-integrity check.

## Trigger

Use for design-system formation, design audit, UX/UI architecture, mobile/web design, inclusive service design, data-intensive dashboards, accessible components, design handover and performance optimization.

## Execution workflow

1. Collect user/product personas, jobs-to-be-done, accessibility and localization requirements, data classification, UX flows, target technology stack, low-connectivity constraints, financial/regulatory exposure and critical actions.
2. Verify official UI UX Pro Max is installed and version-pinned in the **authorized** target working directory. If it is absent, do not claim to run its search engine. Follow the integration runbook in the staging PR.
3. Generate design-system recommendations when engine is available; separate machine-generated patterns from independently validated requirements. Record provenance, assumptions, and design tokens.
4. Enforce inclusive multi-channel UX: smartphone/PWA, low-end browser, SMS/USSD/IVR, agent-assisted and offline/delayed synchronization where business flows require them.
5. Align with applicable PEFY-GG policies: ΩAEIF lifecycle/evidence gates, ΩCSF security and privacy, ΩRCIAF regulations, ΩVIF analytical interface governance and ΩWEBFORGE brand/design engineering.
6. Validate WCAG 2.2 AA as a target (unless stricter applicable rule), keyboard/focus/zoom, semantics, readable contrast, clear validation/error state, text expansion, forms and assistive technology, RTL where relevant, culturally appropriate localization and nonvisual channel usability.
7. Require human review for regulated, financial, HSE, safety- or security-relevant decisions. Never perform irreversible actions based only on UI suggestion.
8. Output components, user journeys, accessibility/security findings, evidence-backed quality metrics, unresolved defects, remediation ownership and deployment readiness.

## Output contract

Provide a concise `UX Decision Record` with: product, country/sector, target user tasks and channels, versions of applicable standards, source package/ref, screenshots/wireframes or implementable code, accessibility/performance test results **or explicit Not Tested**, risks, owners, next approved action.

## Risk policy

No credential/sensitive data leakage to design assistants; least privilege; no dark patterns; version and supply-chain controls; independent design testing; rollback and telemetry; record third-party asset licences. AI proposals are not accessibility conformance certificates.

## Installation status semantics

Do not conflate an available GitHub directory or pull request with installed skills in ChatGPT, Codex or other PEFY-GG repositories. Installation requires its own runtime/host-level verification.
